# 原型版本说明 v0.3.0

本版本只更新 `unity-prototype` 分支；未修改 `main`。本版本将主菜单、皮肤持久化、暂停/投降/结算、战略建筑与可配置生产队列接入现有六角格战斗原型。

## 新增脚本

- `UnityScripts/HexGameFlowController.cs`：主菜单、选关、单位图鉴、皮肤图鉴、皮肤选择、本地全局存档、音量与全屏设置、局内暂停菜单、投降确认和胜负结算。
- `UnityScripts/HexBuildingEconomy.cs`：建筑占领、归属颜色、AP 收入、驻扎恢复、劳动力与矿产资源占用、工厂生产队列。
- `UnityScripts/HexUnitDemo.cs`：接入上述系统、通用建筑占领、皮肤奖励宝箱、AP 时间推进、胜负判定和工厂生成单位。

`HexUnitDemo` 会自动查找或添加 `HexBuildingEconomy` 和 `HexGameFlowController`。建议将它们与 `HexBattlefieldDemo`、`HexUnitDemo` 挂在同一个场景物体上，方便在 Inspector 配置。

## 进入游戏

1. 使用 Unity 6.3 LTS 打开项目的 `unity-prototype` 分支。
2. 确认场景对象上有 `HexBattlefieldDemo` 和 `HexUnitDemo`。首次运行时会加载单位数据、建立菜单与经济管理器。
3. Play 后应进入主菜单，选“选择关卡”→“Test001”→选择“基础皮肤”→“开始 Test001”。
4. 战斗中按 Esc 或点击“局内菜单（Esc）”打开暂停菜单。投降会进入失败结算；大本营被敌方占领也会判定失败。
5. 皮肤解锁、当前皮肤、音量与全屏状态使用 Unity `PlayerPrefs` 保存在本地；单局单位/建筑/生产状态在重开关卡时重置。

## 皮肤配置

在 `HexGameFlowController` 的 **Skin Catalog** 中添加皮肤：

- `id` 必须是唯一的稳定 ID（例如 `heavy_firepower`），不要只依靠显示名称。
- 配置名称、说明及攻击、生命、防御、移动与制造费用倍率。倍率 `1` 表示不变；大于 `1` 表示增加，小于 `1` 表示削弱。
- 基础皮肤默认解锁。其他皮肤通过奖励宝箱解锁，也可将 `unlockedByDefault` 设为 true 供测试。

在 **Skin Chests** 中设置宝箱坐标、奖励皮肤 ID、生命值和显示名称。奖励皮肤 ID 必须与 Skin Catalog 中的 ID 完全一致。宝箱目前用临时图标显示，击败后永久解锁对应皮肤；本地存档中已解锁的皮肤不会重复解锁。

## 建筑与经济配置

`HexBuildingEconomy` 的 **Initial Buildings** 中含一套 Test001 演示布局，可在 Inspector 修改坐标、种类和归属。默认玩家阵营 ID 为 0，敌方为 1，无主建筑为 -1。

目前建筑收入按 AP 结算：
- 大本营：每 AP +1 金钱、每次占领 +2 劳动力；每 20 AP 驻扎地面单位恢复 10 HP、1 弹药、2 燃料。
- 大城市：每 AP +3 金钱、每次占领 +1 劳动力；每 40 AP 驻扎地面单位补充 1 弹药、2 燃料。
- 小城市：每 AP +2 金钱、每次占领 +1 劳动力；每 40 AP 驻扎地面单位补充 1 弹药、2 燃料。
- 乡村：每 AP +1 金钱、每次占领 +1 劳动力；每 40 AP 驻扎地面单位补充 1 燃料。
- 兵工厂、战车工厂、火炮工厂、造船厂、机场：对应类别单位每 10 AP 恢复 10 HP、1 弹药、2 燃料。
- 铁矿和铝矿分别为当前阵营提供 1 点可用资源容量；制造项目启动时临时占用劳动力与矿产容量，制造完成或项目取消时释放占用。

起始金钱和劳动力可通过 Inspector 调整。当前劳动力/矿产采用“可用库存/当前来源容量”展示。丢失矿区而造成生产项目占用量超过当前容量时，该项目以每 AP +0.5 进度运行（50% 速度），且不允许启动不满足资源条件的新项目。

## 配置生产项目（数值待设计）

因为尚未收到 25 种单位各自的最终造价、制造 AP、劳动力/铁矿/铝矿需求，本版本没有擅自编造单位生产成本。要开放生产，请在 `HexBuildingEconomy` 的 **Production Profiles** 中配置：

- `unitId`：必须匹配 `GadgetUnitProfiles.json` 中的单位 ID。
- `displayName`：生产界面显示名称。
- `productionAP` 和 `moneyCost`：制造所需 AP 与金钱。
- `labourRequired`、`ironRequired`、`aluminiumRequired`：生产期间临时占用的资源。
- `allowedBuildings`：允许生产该单位的工厂类型。没有配置有效工厂类型的条目不会出现在工厂生产列表中。

当前每座工厂同一时间处理一个生产项目。金钱在开始制造时扣除；劳动力与矿产为临时占用。工厂易手时，原阵营未完成的生产项目会取消并释放资源占用，不会直接把未完成项目转给新占领方。制造完成后，系统会尝试在工厂所在格或相邻空格生成单位；若没有合适空格，生产项目会保持已完成状态等待空位。

## 原型限制

- 目前选关仅配置了 Test001；更多关卡入口为占位状态。
- 建筑采用临时的圆柱标记与文字标签。还没有建筑专属美术资源，也没有完整的多方混战 AI；归属与经济数据结构保留了扩展方向。
- 生产数值需要根据实际设计补齐，不应把 Inspector 示例配置当作已平衡的最终数据。
- 资源收入、维修和生产只在 AP 时间轴推进时结算；当前原型中模拟时间在等待可行动的我方单位时以离散事件方式推进。
- 本次改动完成了静态源码结构检查，但尚未在 Unity 编辑器中进行 C# 编译和实际运行验证。请在 Unity 6.3 LTS 中编译并验证菜单流程、投降、胜负、单位生成、资源短缺与建筑易手场景。
