## 2. 经验与军阶：已实现的具体数值

经验代码位于 HexUnitDemo.cs 的 GrantExperience、ApplyDamageAndAwardExperience 与 RankFromExperience。

| 规则 | 当前代码行为 |
|---|---|
| 行动获得经验 | 单位结束一次行动时获得等于非移动行动 AP 消耗的经验；移动 AP 本身不计入这部分经验。 |
| 承受伤害获得经验 | 目标每损失 1 点实际生命，获得 2 点经验；按实际扣除 HP 计算。 |
| 击毁目标奖励 | 目标被击毁时，攻击方额外获得目标当前累计经验的 50%（向下取整）。攻击方不会因普通命中自动获得与造成伤害等量的经验。 |
| 军阶门槛 | 0–999：列兵；1000：一条杠；2600：两条杠；5000：将星。经验上限为 5000。 |
| 每次晋升 | 最大生命 +10；若当前 HP 大于 0，当前生命也 +10，不会借晋升复活已经被击毁的单位。 |
| 攻击成长 | 每个军阶使攻击达到基础攻击力的 110%、120%、130%。 |
| 经验持久化 | 🟡 只保存在本局运行时单位对象中；结束/重开一局后不会保留。 |

**经验模块的状态：已实现，可在 Unity 中验证和平衡。** 目前没有单独的经验曲线/奖励数据表，也没有跨关卡单位成长存档。

## 6. 需要在 Unity 编辑器做的事情

### 第一步：确认脚本和数据位于 Unity 工程的 Assets 内

当前 GitHub 仓库源码目录是根目录下的 UnityScripts；仓库根目录本身没有标准 Unity 项目的 Assets 和 ProjectSettings 目录。

- 如果你使用的是独立 Unity 工程，请把 UnityScripts 中的 .cs 文件复制/同步到该工程的 Assets/Scripts/Prototype/（或你已使用的脚本目录）。
- 避免同时保留同一份类的重复副本，否则会出现类重复定义的编译错误。
- 将 GadgetUnitProfiles.json 放到该工程的 Assets/Resources/GadgetUnitProfiles.json。
- 要加载现有像素帧，确保图片位于脚本配置的 Assets/Resources/GadgetSprites/MU_00000/frames/down_right 等 Resources 目录；否则会使用占位图。

### 第二步：挂载组件

在现有 Test001 场景中，选中当前已挂有 HexBattlefieldDemo 和 HexUnitDemo 的同一个地图管理对象：

1. 添加 HexBuildingEconomy。
2. 添加 HexGameFlowController。
3. 确认场景中没有重复的管理组件或重复脚本类。

HexUnitDemo 有自动添加管理器的兜底逻辑；但为了在 Inspector 中编辑建筑、生产项目、皮肤与宝箱，建议手动挂载。

### 第三步：配置建筑

在 HexBuildingEconomy 的 Initial Buildings 中：

- 检查所有坐标在地图边界内。
- 检查建筑与初始单位是否重叠。默认蓝方起始格 (1,1)、红方起始格 (7,7) 分别与双方大本营重叠，这是当前原型布局。
- 检查城市坐标确实落在 City 地形上，否则建筑只是标记，无法同步原有城市地块归属。
- 可调整起始金钱与劳动力；先不要把 500/2 视为最终平衡值。

### 第四步：配置皮肤与宝箱

在 HexGameFlowController 的 Skin Catalog 中新增皮肤，保证 ID 唯一；倍率 1 表示不变，大于/小于 1 分别表示增强/削弱。在 Skin Chests 中配置坐标和奖励皮肤 ID，奖励 ID 必须存在于 Skin Catalog。

首轮建议只测试基础皮肤；流程稳定后再加一款“攻击上升、制造费用上升”的测试皮肤。

### 第五步：配置单位制造

在 HexBuildingEconomy 的 Production Profiles 中逐个新增单位：

- unitId 必须匹配 JSON 中已有的单位 ID。
- allowedBuildings 至少选择一种可生产该单位的工厂类型。
- 填写 moneyCost、productionAP、labourRequired、ironRequired、aluminiumRequired。

最终数值尚未定之前，生产系统只是可配置框架。不要为了让按钮出现而随机填写数字。

### 第六步：编译并按顺序测试

1. 等 Unity 完成导入，先看 Console 第一条红色编译错误；有编译错误时先不要继续调 Inspector。
2. Play 后应显示主菜单；选择 Test001、基础皮肤并开始。
3. 验证选择/移动/攻击/占领、经验与军阶、AP 时间轴，以及右上/右下面板是否遮挡地图。
4. 验证投降→失败结算→重玩；再验证大本营易手判负/判胜。
5. 调整测试皮肤，重开 Test001，确认属性倍率；击败宝箱后确认皮肤解锁，停止 Play 后再次运行确认存档。
6. 配置一条低成本测试生产项目，验证扣钱、资源占用、进度、工厂易手取消，以及出厂格被堵时等待空位。
7. 测试矿区被夺导致资源短缺，确认生产速度减半、可用资源不显示负数、新生产按钮禁用。

如果出错，优先保留 Console 第一条红色错误及其完整堆栈，不要只发最后一条报错。
